# Proxmox v1 — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.

**Goal :** surveiller le nœud Proxmox, ses VM/LXC et ses stockages depuis l'onglet Stats, en lecture seule.
**Architecture :** `ServiceHttp` reçoit un transport injectable ; Proxmox utilise le plugin natif `PinnedHttp` (TLS auto-signé sur IP privée + empreinte TOFU). `services/proxmox.ts` gère login/ticket/normalisation, `store/proxmox-store.ts` le polling et les débits, `StatsPage` le sélecteur.
**Tech :** Vue 3, Pinia, Vitest, Capacitor 8, Java (plugin local enregistré dans `MainActivity`).
**Spec :** `docs/superpowers/specs/2026-11-25-proxmox-design.md` · **Maquette :** `design-mockups/proxmox.html`

## Global Constraints
- Toute requête passe par `ServiceHttp` (`src/services/http.ts`), jamais `fetch`.
- Secrets (mot de passe) → `@capacitor/preferences` ; empreinte (non secrète) → `services.proxmox.certSha256`, persistée par pinia.
- Le ticket n'est jamais persisté.
- Format d'empreinte : 32 octets en hex majuscule séparés par `:` (comme la GUI Proxmox).
- Libellés exacts : `Machine`, `Proxmox`, `VM & conteneurs`, `en marche`, `éteints`, `Certificat changé`, `Faire confiance au nouveau`, `Réglages`, `Mémorisé`, `Reçu`, `Certificat auto-signé mémorisé`, `Identifiant ou mot de passe incorrect`, `Proxmox se joint par son IP locale en https (ex. https://192.168.1.10:8006)`.
- On ne commite rien sans demande explicite.

## Review Focus
1. Empreinte différente : aucune requête n'emporte le mot de passe ni le ticket ; l'UI montre l'alerte, pas une erreur réseau générique. (Tasks 1, 2, 4)
2. Ticket expiré (401 en plein polling) : un seul re-login, puis la requête repasse ; un 2ᵉ 401 donne une erreur, pas une boucle. (Task 3)
3. Premier relevé : aucun débit réseau n'est encore calculable → `—`, pas `NaN` ni un pic énorme ; compteur qui recule (VM redémarrée) → 0. (Task 4)
4. Adresse `https://pve.domaine.com` ou `http://192.168.1.10:8006` : erreur explicite au test, rien n'est envoyé. (Tasks 1, 5)
5. Onglet Proxmox masqué ou page quittée : le timer de 5 s s'arrête (pas de polling en fond). (Task 6)

### Task 2 : Transport injectable dans `ServiceHttp`
**Files :** Modify `src/services/http.ts`. Create `src/services/pinned-transport.ts`. Test `src/services/pinned-transport.test.ts`.
**Consumes :** Task 1 (`PinnedHttp`).
**Produces :**
- `export type HttpTransport = (req: { url: string; method: string; headers: Record<string,string>; data?: unknown; timeoutMs: number }) => Promise<{ status: number; headers: Record<string,string>; data: unknown }>`
- `new ServiceHttp(baseUrl, apiKey, authHeader = "X-Api-Key", transport: HttpTransport = capacitorTransport)` — le comportement actuel devient `capacitorTransport`, inchangé.
- `export class CertMismatchError extends HttpError` (`kind: "cert"`, champ `received: string`) ; `HttpErrorKind` gagne `"cert"`.
- `createPinnedTransport(getPin: () => string | undefined, onFirstSeen: (fp: string) => void): HttpTransport` — sur web (`!Capacitor.isNativePlatform()`) renvoie `capacitorTransport`.
- [ ] Tests (plugin mocké avec `vi.mock("@/plugins/pinned-http")`) :
  - sans pin, la réponse `{fingerprint:"AA:…"}` appelle `onFirstSeen("AA:…")` ;
  - avec pin, `onFirstSeen` n'est pas appelé ;
  - un rejet `{code:"cert_mismatch", data:{fingerprint:"BB:…"}}` devient `CertMismatchError` avec `received === "BB:…"` ;
  - `data` texte JSON est parsé ; un corps vide donne `null` ;
  - les tests existants de `src/services/*.test.ts` passent toujours (`npm test`).
- [ ] RED, implémentation, GREEN.

### Task 3 : Client Proxmox

**Consumes :** Task 2.
**Produces :**
- Types : `PveNode { node; cpu: number /*%*/; cores; memUsed; memTotal; swapPercent?; load1?; uptime; version? }`, `PveGuest { vmid; name; type: "qemu"|"lxc"; running: boolean; cpu: number /*%*/; cores; memUsed; memTotal; diskUsed?: number /*absent pour qemu*/; diskTotal; netIn: number /*cumulé*/; netOut; uptime; tags: string[]; template: boolean }`, `PveStorage { id; type; used; total; percent }`, `PveSnapshot { node: PveNode; guests: PveGuest[]; storages: PveStorage[] }`.
- `createProxmoxClient(cfg: { url: string; username: string; password: string; transport: HttpTransport })` → `{ login(): Promise<string /*version*/>; snapshot(): Promise<PveSnapshot>; guestIp(g: PveGuest, node: string): Promise<string | undefined> }`.
- `proxmoxUrlError(url: string): string | undefined` — renvoie le libellé exact des Global Constraints si le schéma ≠ https ou l'hôte n'est pas une IPv4 RFC 1918.
- Fonction pure `sortGuests(guests: PveGuest[]): PveGuest[]`.
- [ ] Tests (transport factice) :
  - `login` poste `username=homelab%40pve&password=…` en `application/x-www-form-urlencoded` sur `/api2/json/access/ticket`, puis les GET portent `Cookie: PVEAuthCookie=<ticket>` ;
  - login 401 → `HttpError` de message `Identifiant ou mot de passe incorrect` ;
  - un GET 401 déclenche exactement un re-login et une nouvelle tentative ; deux 401 de suite → erreur, 2 logins au total ;
  - `snapshot` à partir d'une réponse `/cluster/resources` contenant 1 nœud, 1 qemu, 1 lxc, 1 template, 1 storage + `/nodes/pve/status` : `cpu` 0.18 → 18, `loadavg ["1.24",…]` → 1.24, `pveversion "pve-manager/8.3.2/…"` → `"8.3.2"`, `tags "media;gpu"` → `["media","gpu"]`, qemu `diskUsed` indéfini, template présent avec `template: true` ;
  - `sortGuests` : en marche par CPU décroissant, puis éteintes par vmid, templates retirés ;
  - `guestIp` lxc lit la 1ʳᵉ `inet` hors `lo` sans le `/24` ; qemu lit l'agent ; un 403/500 → `undefined` ;
  - `proxmoxUrlError` : `https://192.168.1.10:8006` → undefined ; `http://192.168.1.10:8006`, `https://pve.domaine.com` → message.
- [ ] RED, implémentation, GREEN.
